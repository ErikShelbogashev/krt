# 0006. Ручной корень композиции без DI-контейнера

Статус: принято, 2026-11-27. **Осознанное отличие от вики.**

## Контекст
Вики: «Порты, операции и ресурсы кодируются классами, которые создаются и связываются DI-контейнером» ([ergo-arch.adoc, «Проекция структуры компонентов → Кодирование блоков»](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/production-code/models/ergo-arch.adoc)). В krt нет Spring и нет другого DI-контейнера; объектов десяток. Вики в той же главе придерживается KISS и предлагает вводить слои только при необходимости.

## Решение
- Ресурсы и операции создаются вручную в одном месте: `krt.infra` (`AppContext` или функция сборки), вызываемом из `main`.
- Порты получают операции из этого контекста; `@Composable`-функции не создают ресурсы сами.
- Жизненный цикл ресурсов (пул потоков `Renderer`) открывается и закрывается в корне композиции.

## Последствия
- Нет новой зависимости. Связи видны в одном файле.
- При росте числа компонентов вопрос пересматривается.
