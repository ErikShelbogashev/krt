# 0003. Порт = обработчик UI-события Compose

Статус: принято, 2026-11-27.

## Контекст
Вики определяет порт как точку входа: контроллер, слушатель очереди, обработчик событий планировщика; метод порта делает один вызов операции или ресурса, когнитивная сложность ≤1 ([ergo-arch.adoc, «Проекция структуры компонентов → Кодирование блоков»](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/production-code/models/ergo-arch.adoc)). В desktop-приложении на Compose точки входа — лямбды `onClick`, `onValueChange`, `onDrag`, `onKeyEvent`. Сами `@Composable`-функции описывают представление и вкладываются друг в друга.

## Решение
- Порт — обработчик UI-события. Он вызывает ровно одну операцию (или один метод ресурса, если эффект один) и не содержит логики, кроме выбора представления ответа.
- `@Composable`-функции — представление. Их вложенность (`settingsPanel` → `CameraSettings`) не считается связью порт→порт.
- Локальное состояние UI (`remember { mutableStateOf(...) }` для положения джойстика, раскрытия меню, текста в поле) — состояние представления, а не ресурс системы.
- Расчёты, которые сейчас живут в обработчиках (дельты yaw/pitch, направление джойстика, проверка размеров кадра), уходят в трансформации.

## Последствия
- Konsist-правило: файлы `krt.app.*` с портами не импортируют `krt.domain.*.model` для вычислений — только операции и представления (уточняется на этапе 6).
- Обработчик, который сейчас делает «записать + перерисовать», превращается в вызов операции (ADR 0004).
