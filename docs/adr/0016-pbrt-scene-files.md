# 0016. Файлы сцен в формате pbrt-v4

Статус: принято, 2026-11-27.

## Контекст
Сцены krt — код на Kotlin, а загрузка ограничена одним OBJ с одним материалом. Нужен физически полный общепринятый формат, в котором живут и встроенные сцены, и сцены пользователя. Выбран формат pbrt-v4: в нём есть спектральные материалы, проводники с измеренными спектрами, дисперсия, шероховатость GGX с анизотропией, среды через `MediumInterface`, площадные источники с чёрным телом, размытие движения через `ActiveTransform`, сетки PLY.

## Решение
- **Совместимость.** Файл, который пишет krt, — валидный pbrt-v4, его рендерит сам pbrt. То, чего pbrt не выражает, записано строкой-комментарием `#krt <Директива> ...` в синтаксисе pbrt перед директивой pbrt, которая это заменяет. pbrt видит только комментарий и рисует запасной вариант, krt берёт `#krt`. Сделаны: `#krt Material` (бархат, тонкая плёнка, процедурные узоры с рельефом, металл с размытием, стекло с подкраской Бэра — Ламберта, шахматка, точная шероховатость и ось шлифовки проводника), `#krt AreaLightSource "pattern"` (узорное свечение), `#krt Shape "fractal"` (ADR 0015, запасная фигура — шар), `#krt Sky` (градиентное небо, запасной вариант — постоянный `infinite`), `#krt Look` (выборка источников, размытие движения), `#krt Name` (имя объекта).
- **Чтение — чистая трансформация** (`krt.i9ns.pbrt`): `PbrtSyntax` (лексемы и директивы), `PbrtReader` (состояние графики pbrt: стек атрибутов, CTM в начале и конце затвора, материалы, текстуры, среды), `PbrtMaterials`, `PbrtTextures`, `PbrtGeometry`, `KrtExtensions`, `Ply`. Ввод-вывод — у ресурса: он спрашивает `PbrtReader.references`, читает названные файлы и передаёт их байты в `read`.
- **Соответствия.** `diffuse` → `Lambert`, `coateddiffuse` → `Plastic`, `conductor` с `metal-Au/Cu/Ag/Al` → `Conductor`, с `reflectance` → `Metal`; `dielectric` с `float eta` → `Dielectric`, со спектром → подгонка Коши (дисперсия), именованные стёкла — таблица Коши; `thindielectric` → плёнка нулевой толщины; `interface` + `MediumInterface` на шаре → `Fog`; `subsurface` → стекло со средой внутри; `homogeneous` среда → `Medium` (σt = σa + σs, альбедо σs/σt). Шероховатость: в pbrt α = √roughness, в krt α = roughness², поэтому `roughness_krt = roughness_pbrt^(1/4)`. Чёрное тело в krt нормировано на яркость 1, как в pbrt.
- **Чего krt не рисует** (камеры кроме перспективной, `curve`, `ObjectInstance`, точечные источники — как маленький светящийся шар, текстуры-картинки) — ближайшая замена и предупреждение в `SceneDescription.warnings`, файл не отвергается. Синтаксические ошибки — `PbrtError` с номером строки.
- **Рукость.** Камера pbrt левосторонняя, krt — правосторонняя. krt пишет `Scale -1 1 1` перед `LookAt`, чтобы pbrt показал ту же картинку; при чтении krt берёт вид из `LookAt`.
- **Запись** (`PbrtWriter`, `PbrtMaterialWriter`, `PbrtLines`) — точная: числа печатаются так, что читаются в тот же double. Сетка больше 512 треугольников уходит в двоичный PLY рядом.

### OBJ со спецификацией материалов
- `ObjScene` (`krt.i9ns.objfile`) читает OBJ + MTL и, если рядом лежат, `render-showcase.json` (схема krt-showcase-target-v1) и `scene-layout.json` пакета GitHub-voxel. Объекты сохраняют имена из `o` (треугольники объекта делят его `id`, выбор источника берёт их как один свет, ADR 0012), каждый угол — свою нормаль из `vn`, грань с одной нормалью на все углы остаётся плоской. Индексы — с 1 или отрицательные.
- Материал объекта — последняя совпавшая привязка (glob со `*`), иначе цвет MTL. Glob без совпадений, повтор имён, ссылка на несуществующий материал — ошибка загрузки (`ObjSceneError`).
- Сцена с layout «Z-up» один раз поворачивается в Y-up krt: (x, y, z) → (x, z, −y) для точек, нормалей, камеры и объёмов. Масштаб не трогается. Камера — из `camera_suggestion`: фокусное расстояние на сенсоре 36 мм в кадре 16:9. Небо — `world_color` из sRGB в линейный свет.
- Типы спецификации: `Dielectric`, `Conductor` (`tangent_axis` — ось объекта по `rotation_deg` layout'а), `Subsurface` (стекло 1.4 и среда по `mean_free_path` RGB внутри; снаружи — дымка, если объект в ней), `Sheen` (бархат, блеск — белый × `sheen`), `Plastic` с текстурами `wood`/`perlin`/`marble` и `bump`, `SoapBubble`, `Iridescent`, `Emissive` (Кельвин или `color_override`, × `intensity`; `object_mask` — светится весь объект, `procedural_grid` и `pulse_stripes` — узоры `GRID` и `STRIPES`), объёмы `Fog`. Неизвестный тип — ошибка.
- Свет из `lighting_suggestion` (площадные лампы Blender в ваттах) не добавляется: свет сцены — её излучающие объекты.

### Ресурс сцен
- `SceneLibrary` (`krt.i9ns.scenefile`) читает демо-сцены из ресурсов `krt/scenes` (раз, с кэшем) и файлы пользователя с диска; разбор — чистые `PbrtReader` и `ObjScene`. Сбор файлов, на которые ссылается сцена (`Include`, `plymesh`), — цикл ввода-вывода внутри ресурса: чистой функцией его не сделать, ссылки находит чистый `PbrtReader.references`.
- Кнопка «Open scene…» открывает `.pbrt` или `.obj` (`OpenSceneOp`) и показывает, что krt нарисовал иначе, чем в файле.

## Последствия
- Встроенные сцены лежат в ресурсах как файлы `.pbrt`; Classic читается из файла побитово тем же, эталон не меняется.
- Вложенные среды и камера внутри сетки со средой не выражаются (ADR 0014).
- Фрактал в настоящем pbrt — шар-заглушка.
