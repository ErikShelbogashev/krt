# 0007. Тесты: JUnit 5, golden-тест кадра, без моков

Статус: принято, 2026-11-27.

## Контекст
Тестов нет. Вики: тесты через публичное API, моки только для трудно воспроизводимого поведения управляемых зависимостей ([testing/principles/test-observalbe-behaviour.adoc](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/testing/principles/test-observalbe-behaviour.adoc)); тест ≤10 с (не больше 30), набор ≤60 с (не больше 300) ([testing/principles/fast-tests.adoc](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/testing/principles/fast-tests.adoc)).

## Решение
- JUnit 5 через `kotlin("test")`.
- Тесты трансформаций — на чистых функциях (пересечения, материалы с фиксированным `Random`, разбор .obj, проекция камеры).
- Тесты операций — через их публичный метод с реальными ресурсами в памяти и реальным `Renderer`; моков нет.
- Golden-тест кадра: демо-сцена с фиксированным seed, малое разрешение, сравнение с эталоном в `src/test/resources`. Эталон перегенерируется только при осознанном изменении поведения.
- Compose UI-тесты на этом этапе не добавляются: порты тонкие (ADR 0003).

## Последствия
- Рефакторинг, меняющий хоть один пиксель эталона, — это изменение поведения и идёт отдельным PR.
