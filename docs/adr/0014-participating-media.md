# 0014. Среды внутри замкнутых поверхностей

Статус: принято, 2026-11-27. Заменяет в ADR 0012 описание тумана через хеш луча и в ADR 0013 — `Translucent` как туман в шаре.

## Контекст
Туман был отдельным объектом-сферой: его `hit` разыгрывал длину свободного пробега хешем луча, а `Translucent` складывал стеклянный шар с таким туманом. Это работало только для шаров. Сцены из пакета GitHub-voxel и формат pbrt-v4 требуют сред внутри любых замкнутых сеток (кожа-коробки, кнопка-цилиндр), с плотностью по каналам и с дымкой вокруг всей сцены, в которой стоит камера.

## Решение
- **Модель.** `Medium` — однородная среда: плотность σt по каналам RGB и альбедо. `MediumInterface(inside, outside)` — среды по две стороны замкнутой поверхности; его несут `Sphere` и `Triangle` (сторона «снаружи» — сторона обхода треугольника), его же отдаёт `Hit`. `Interface` — материал границы, которую свет проходит без изменений (край тумана). `Fog` — сфера из `Interface` со средой внутри, `Translucent` — стеклянная сфера со средой внутри.
- **Путь помнит среду.** Ядро (`PathTracing`) хранит текущую среду пути. Луч, прошедший поверхность со средами (направление после рассеяния — по другую сторону нормали), попадает в среду `inside` через лицевую сторону и в `outside` через обратную. Между поверхностями путь может рассеяться на частице среды. Пересечение `Interface` не считается отскоком.
- **Свободный пробег (`FreeFlight`).** Расстояние разыгрывается по плотности случайного канала, вес — средний по каналам pdf (спектральный MIS), поэтому цветная плотность несмещённая. Без сред ядро не тянет ни одного лишнего случайного числа: эталон Classic прежний.
- **Свет через среды.** Теневой луч проходит границы `Interface` (до 8) и умножается на пропускание сред по пути; твёрдая поверхность его гасит. Частицы среды, закрытой твёрдой поверхностью (воск в стекле), источники не выбирают: теневой луч всё равно упрётся в стену.
- **Камера в тумане.** Луч камеры начинается в среде тумана, внутри которого стоит камера (`TraceScene.mediumAt`, `GpuScene.mediumAt`). Для сеток эта проверка не делается: камера внутри замкнутой сетки со средой не поддерживается.
- **GPU.** В записи примитива — номера сред изнутри и снаружи, среды — отдельный раздел текстуры. Шейдер повторяет состояние пути: текущая среда, «закрыта ли», отдельный счётчик отскоков. Пересечения границ ограничены общим числом шагов пути (48).

## Последствия
- SSS — честное случайное блуждание в любой замкнутой сетке на CPU и GPU, туман — любой формы.
- Сцена с дымкой вокруг всего дороже: каждый луч разыгрывает пробег.
- Вложенные среды выражаются только явным `outside` у внутреннего объекта: стека сред у пути нет.

## Дополнение, 2026-11-28: фазовая функция Хеньи — Гринштейна

Частица рассеивала свет поровну во все стороны, и лучи сквозь отверстия в дымке выходили слабыми: настоящая дымка рассеивает в основном вперёд. У среды появился параметр `g`, средний косинус рассеяния (в pbrt-v4 это `"float g"` у `homogeneous`): 0 — поровну во все стороны, к 1 — всё больше вперёд. Плотность рассеяния p(cosθ) = (1 − g²) / (4π (1 + g² − 2g cosθ)^{3/2}), направление выбирается точно по ней (обращением её функции распределения), поэтому вес пути — по-прежнему альбедо. Выборка источников умножает свет на p(cosθ) между направлением, откуда пришёл луч, и направлением на источник. При g = 0 ядро тратит те же случайные числа, что и раньше, кадры сред не меняются. В шейдере у среды седьмое значение — g.
