# 0002. Случайность передаётся в вычисления параметром

Статус: принято, 2026-11-27.

## Контекст
Трассировка — метод Монте-Карло. Сейчас вычисления (`Camera.ray`, `Material.scatter`, `Point3.random*`, генерация демо-сцены, перемешивание пикселей) берут глобальный `kotlin.random.Random`. Вики запрещает трансформациям обращаться к глобальному окружению ([ergo-arch.adoc, «Проекция структуры поведения → Кодирование блоков», п.3](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/production-code/models/ergo-arch.adoc); [principles/operations/pure-functions.adoc](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/production-code/principles/operations/pure-functions.adoc)). Без детерминизма нельзя написать тест кадра, а значит нельзя доказать, что рефакторинг не меняет поведение.

## Решение
- Все вычисления, которым нужна случайность, принимают `random: kotlin.random.Random` параметром.
- Источник случайности создаёт только ресурс `Renderer` (по экземпляру на задачу рендера) и корень композиции; seed по умолчанию берётся из `Random.Default`, в тестах фиксируется.
- `System.currentTimeMillis()` для тайминга перерисовки остаётся внутри ресурса `Renderer` (это ввод, а не трансформация); решение «пора ли перерисовать» — чистая функция от переданного времени.
- id объектов сцены (`UUID.randomUUID()`) — значение по умолчанию в конструкторе, что вики допускает.

## Последствия
- Golden-тест кадра с фиксированным seed (ADR 0007).
- Один дополнительный параметр в горячем пути; пул потоков не делит один `Random` между потоками.
- Многопоточный рендер с перемешиванием пикселей недетерминирован по порядку записи, но не по значениям: значение пикселя зависит только от seed пикселя. Seed пикселя выводится из seed задачи и координат.
