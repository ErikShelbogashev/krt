# 0004. Перерисовка вызывается явно из операций

Статус: принято, 2026-11-27.

## Контекст
Каждый обработчик сейчас делает два эффекта: меняет один ресурс (камеру, сцену, настройки) и вызывает `RenderController.renderImage`. Можно сохранить явный вызов или сделать рендер реактивным (подписка на изменения ресурсов). Вики требует явного потока управления в действиях ([ergo-code-imperatives.adoc, «Дизайн функций»](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/production-code/ergo-code-imperatives.adoc)) и описывает переиспользуемую последовательность эффектов как доменную операцию ([ergo-arch.adoc, «Номенклатура блоков модели компонентов»](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/production-code/models/ergo-arch.adoc)).

## Решение
- Перерисовка — доменная операция `renderFrame(scene, cameraState, renderSettings, renderer)`: top-level функция с ресурсами в параметрах, не класс с состоянием. Она читает снимки трёх ресурсов и передаёт их ресурсу `Renderer`.
- Операции «изменить X» — классы `*Op` с одним публичным методом: запись в ресурс X, затем `renderFrame`.
- Реактивная перерисовка не вводится: это изменение поведения, отдельная задача.

## Последствия
- Порядок «записать, затем перерисовать» виден в коде каждой операции.
- У каждой операции до 4 зависимостей (ресурс X + три ресурса рендера), в пределах порога.
