# 0009. Отдельный GPU-режим рендера

Статус: принято, 2026-11-27.

## Контекст
ADR 0008 закрепил требование владельца: каждый пиксель кадра считается на CPU кодом на Kotlin, GPU-шейдеры не используются. Владелец попросил добавить отдельный GPU-режим как опцию и выбрал для него шейдер Skia (SkSL) через Skiko.

Варианты, которые рассматривались:
- шейдер Skia (SkSL) через Skiko — без новых зависимостей, на macOS исполняется через Metal, а программный бэкенд Skia исполняет тот же шейдер без видеокарты, поэтому его можно тестировать на CI;
- WebGPU compute (wgpu, WGSL) — полноценные compute-шейдеры, но новая нативная библиотека, а на CI без GPU тесты пропускались бы;
- OpenGL через LWJGL — на macOS OpenGL устарел и остановился на версии 4.1, compute-шейдеров нет.

SkSL — подмножество GLSL ES 2.0: нет рекурсии, у циклов постоянная граница, нет побитовых операций и целочисленного остатка от деления.

## Решение
**CPU остаётся основным режимом.** Кадр по умолчанию считается на CPU кодом на Kotlin (ADR 0008). Golden-тесты, бенчмарки и правило «пиксели на CPU» относятся к нему. GPU-режим включается кнопкой в UI и не меняет CPU-путь.

**GPU-режим — записанное исключение.** В нём кадр считает SkSL-шейдер на видеокарте. Шейдер рисуется прямо в Compose-холсте окна, в контексте Skia, который Compose уже держит на GPU. Готовый кадр не возвращается в буфер пикселей CPU.

**Разделение по пакетам.**
- Упаковка сцены для шейдера — чистая трансформация в ядре `krt.domain.trace`: из списка объектов модели получаются массивы чисел и байтов. Без Skia, без I/O, тестируется напрямую.
- Ресурс `GpuTracer` в `krt.domain.render` скрывает внешнюю систему, видеокарту через Skia. Он компилирует шейдер один раз, собирает из упакованной сцены и параметров камеры объект `Shader` и освобождает скомпилированный шейдер при закрытии. Им пользуется только `RenderController`.
- Текст шейдера лежит отдельным файлом в ресурсах, рядом с `GpuTracer`.
- Представление в `krt.app` рисует готовый `Shader` кистью, логики в нём нет.

**Данные сцены.** Геометрия сфер (центр и радиус) передаётся массивом uniform на 512 сфер: к нему шейдер обращается на каждом луче, и это быстрее текстуры. Сферы сверх 512 в GPU-режиме не рисуются. Материалы передаются текстурой RGBA_8888, к ней шейдер обращается только в точке попадания. Каждое число занимает один тексель: 24 бита с фиксированной точкой в каналах R, G, B, альфа всегда 255. Float-текстуры через Skiko не используются: на проверенной версии Skiko перечисление `ColorType` для float-форматов не совпадает с нативным, и данные искажаются. Текстура без цветового пространства, поэтому Skia не пересчитывает её цвета.

**Случайность** в шейдере своя: хеш от координат пикселя, номера сэмпла и сида кадра. Сид кадра приходит из CPU параметром (ADR 0002). Кадр совпадает с CPU-кадром статистически, а не побитово.

**Проверки.**
- Упаковка сцены: прямое тестирование трансформации.
- Шейдер исполняется в тестах на программном бэкенде Skia. Сверка с CPU-кадром той же сцены идёт по средней яркости в пределах шума, а не по эталону.
- Konsist: ядро по-прежнему не зависит от Skia, Compose, AWT и Swing.

## Последствия
- Появляется второй язык кода, SkSL. Новый тип объекта или материала нужно добавить в двух местах: в модель для CPU и в упаковку и шейдер для GPU.
- Глубина отражений и число сэмплов в шейдере ограничены константами, это ограничение SkSL.
- В GPU-режиме нет прогрессивного рендера: кадр считается за один проход со всеми сэмплами.
- Координаты сфер передаются как float32, параметры материалов с шагом около 0,0005 в пределах ±4096.
- Треугольники (OBJ-модели) в первой версии GPU-режима не рисуются, их и BVH добавит отдельный PR.

## Дополнение, 2026-11-27: кадр рисуется один раз

Шейдер, нарисованный прямо в Compose-холсте, Skia исполнял заново при каждой перерисовке окна: наведение на кнопку, перетаскивание ползунка и мигание курсора стоили полного прохода трассировщика. При вписывании кадра в окно шейдер к тому же считался для каждого пикселя экрана, а не кадра. На кадре 400×400, 5 сэмплов, 486 сфер одна перерисовка занимала около 400 мс.

Готовый кадр нужно держать в текстуре на GPU. Контекст Skia, в котором Compose рисует окно на GPU, публично не доступен, поэтому своей поверхности на нём не создать. Растровая поверхность перенесла бы шейдер на CPU, а это противоречит смыслу режима.

Поэтому представление записывает кадр в картинку (`Picture`). Шейдер заливает прямоугольник кадра его размера, фильтр изображения масштабирует результат под окно, и картинка становится шейдером картинки. Skia отрисовывает шейдер картинки в текстуру на GPU при первом использовании и при следующих перерисовках берёт текстуру из своего кэша. Шейдер исполняется один раз на пиксель кадра, а кадр масштабируется так же, как кадр CPU.

Последствия:
- Новая картинка создаётся только при новом кадре или новом масштабе. Создавать её при каждой перерисовке нельзя: кэш Skia привязан к картинке.
- Картинку, шейдеры и текстуру освобождают Skiko и кэш Skia, когда на них не остаётся ссылок. Закрывать их явно нельзя: записанный Compose список команд может ссылаться на них до следующей перерисовки.
- Сохранить GPU-кадр в PNG по-прежнему нельзя: он не возвращается в буфер пикселей CPU.
