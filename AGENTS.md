# Правила проекта krt

krt — десктопный трассировщик лучей на Kotlin + Compose Desktop. Код пишется по [Эргономичной архитектуре](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/production-code/models/ergo-arch.adoc) (ЭА) А. Жидкова. Отличия от неё и адаптации к desktop записаны в [docs/adr](docs/adr/README.md). Если правило ниже и вики расходятся, а ADR нет — это ошибка правил: сверься с вики и заведи ADR.

Сборка и тесты: `./gradlew check`. Запуск: `./gradlew run`.

## Словарь

- **Порт** — обработчик UI-события Compose (`onClick`, `onValueChange`, `onDrag`, `onKeyEvent`). Делает один вызов операции или ресурса. Логики нет. ([ADR 0003](docs/adr/0003-ports-in-compose.md))
- **Представление** — `@Composable`-функция. Вкладывается в другие представления, держит только состояние UI (`remember`).
- **Операция (`*Op`)** — класс с одним публичным методом, оркестрирует эффекты над ресурсами. Создаётся в корне композиции.
- **Доменная операция** — переиспользуемая последовательность эффектов. Top-level функция с ресурсами в параметрах, не класс-синглтон. Пример: `renderFrame`. ([ADR 0004](docs/adr/0004-explicit-render.md))
- **Ресурс** — долгоживущий объект, который хранит изменяемое состояние (`Scene`, `CameraState`, `RenderSettingsState`) или скрывает внешнюю систему (`Renderer` — пул потоков и кадр, `ObjFileReader` — файловая система). Ресурс используется либо одним другим ресурсом, либо любым числом операций.
- **Эффект** — чтение или запись ресурса.
- **Трансформация (вычисление)** — чистая функция. Единственное место логики. Противоположна эффекту.
- **Модель** — неизменяемые `data class`/значения (`Point3`, `Sphere`, `Camera`, `RenderSettings`). ([ADR 0005](docs/adr/0005-immutable-model.md))

## Пакеты

Корень `krt`. Подробно — [ADR 0001](docs/adr/0001-package-layout.md).

| Пакет | Что лежит | Что не лежит |
| --- | --- | --- |
| `krt.app.<фича>` | порты, представления, операции одной фичи UI (`camera`, `scene`, `render`) | ресурсы, модели, логика |
| `krt.domain.<ресурс>` | класс ресурса в корне пакета | UI, Compose |
| `krt.domain.<ресурс>.model` | неизменяемые модели и трансформации над ними | ввод-вывод, Compose, AWT, потоки |
| `krt.domain.<ресурс>.{views,commands,queries}` | DTO представлений, команд, параметров запросов — только когда появятся | классы-читатели |
| `krt.i9ns.<система>` | ресурсы внешних систем (файловая система) | логика разбора — она в трансформации рядом |
| `krt.infra` | корень композиции: создание и связывание ресурсов и операций, жизненный цикл ([ADR 0006](docs/adr/0006-manual-composition-root.md)) | логика |
| `krt.platform.<тема>` | переиспользуемый код без предметной области: математика, конвертация в AWT | ссылки на `app`/`domain` |

Зависимости идут только вниз: `app → domain, i9ns, platform`; `domain → platform`; `infra` знает всех. Циклов нет ни между пакетами, ни между классами.

## Компоненты

- Порт не зависит от порта. Операция не зависит от операции: общее выносится в доменную операцию.
- Интерфейс вводится только при двух и более production-реализациях (`Material`, `Traceable`). Для тестов интерфейсы не вводятся.
- Связей у компонента не больше 4 желательно, не больше 8 строго.
- Ресурс, открывший пул потоков/файл, сам же его и закрывает; корень композиции закрывает ресурсы при выходе.

## Поведение

Операция строится в сбалансированной форме: ввод → трансформация → вывод ([ergo-arch.adoc, «Проекция структуры поведения»](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/production-code/models/ergo-arch.adoc)).

- В вводе, выводе и оркестрации (порты, операции, доменные операции, методы ресурсов) **нет ветвлений и циклов, включая `map`/`filter`/`forEach`/`for`**, кроме guard clause.
- Трансформации **не обращаются к глобальному окружению**: `Random`, `System.currentTimeMillis()`, `Instant.now()`, переменные окружения приходят параметрами ([ADR 0002](docs/adr/0002-randomness-as-parameter.md)). Исключение — значение id по умолчанию в конструкторе модели.
- Модели неизменяемы, изменяемые типы не выходят за границы вычисления. Локальная мутация внутри вычисления допустима.
- В функции не больше двух доменов: математика сцены и AWT/Compose смешиваются только в функциях конвертации (`krt.platform.awt`).

## Объявления верхнего уровня

По [patterns/kotlin/top-level-declarations.adoc](https://github.com/ergonomic-code/ergo-wiki/blob/2b77b9c/kb/production-code/patterns/kotlin/top-level-declarations.adoc):
- простые утилиты и константы, локальные для файла, — `private` top-level;
- сложная логика, требующая отдельного теста, и глобальные утилиты/константы — в объекте-неймспейсе (например `object JoystickRules`) или методом модели;
- публичные top-level — только для повсеместных объявлений (операторы `Point3`) и доменных операций.

## Тесты

[ADR 0007](docs/adr/0007-testing.md). JUnit 5; трансформации — напрямую, операции — через публичный метод с реальными ресурсами, без моков. Golden-тест кадра с фиксированным seed: изменение эталона = изменение поведения, отдельный PR. Тест ≤10 с, набор ≤300 с.

## Пороги

Когнитивная сложность: метод порта ≤1, действие (операция, ресурс) ≤4, трансформация ≤15. Связи ≤4/≤8. Проверяются detekt и Konsist в `./gradlew check`.

## Как вносить изменения

- Каждый коммит — либо рефакторинг, либо изменение поведения, не оба сразу. Рефакторинг не меняет смысл тестов.
- Небольшие PR, одна тема на PR, `./gradlew check` зелёный на каждом коммите.
- Перенос пакетов — отдельными коммитами без правок логики.
